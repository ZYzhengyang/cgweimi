Done. Here's what was fixed:

**Problem:** Category buttons in Explore page updated `activeCategory` state and refreshed the banner, but `MkWaterfall` had no awareness of the selected category — it always loaded the same unfiltered local timeline data.

**Changes:**

1. **`MkWaterfall.vue`** — Added `category` prop and imported `getCategoryTagMap` from the categories config. When `category` is set (and isn't `'all'`), the component looks up the corresponding tags and passes `params.tag` to the `notes/local-timeline` API call.

2. **`explore.works.vue`** — Bound `:category="activeCategory"` on the `<MkWaterfall>` component so the selected category is passed through.

The flow is now: click category button → `activeCategory` changes → `waterfallKey` increments (forces re-mount) → `MkWaterfall` receives new `category` prop → API call includes `tag` parameter → filtered results display.
